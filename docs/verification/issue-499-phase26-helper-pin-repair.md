## Repair, no acceptance shortcuts

1. The tracked Aqua LaunchAgent template now has exactly three fields. The installer derives and verifies both frozen SHA-256 identity values from the exact clean git HEAD and **current installed, signed helper**; caller-provided arbitrary values are forbidden. Only the previous byte-exact legacy plist may migrate; any foreign plist, symlink, write-permission issue, signing drift or changing source fails closed. The original plist is archived privately before replacement.
2. Installer acquires the global native owner lock, boots out the old loaded job, waits for departure, atomically publishes the authenticated new plist, bootstraps the direct user-Aqua service and requires both pins in `launchctl print` and a **new** PID with fresh Accessibility status. It then issues exactly ONE independent private no-edit request to the newly running helper; Swift itself must execute the unmodified `NativeRollPins.verify` and report `pin-verified` using canonical signed-actor/source values. No Resolve SDK, window focus, AX event, Roll or project selection occurs in the probe.
3. The no-edit protocol has a separate operation name, filename namespace, parser flag, durable one-use probe claim, and reply shape. It cannot enter `FixedRoll.execute`; conversely a real Roll request cannot parse as a no-edit probe. A physical restart skips historical already replied/consumed one-use requests. New Roll claims a durable admission marker even before the effect-specific Roll journal, so a pre-effect refusal is not replayed after restart.
4. Signed `build.sh` compares the *designated requirement* of new and old helper before any replacement, and preserves the old signed bundle in a private SHA-256-addressed archive. It never deletes M4 evidence, old helper app archives, or the private spool. The exact signing identity must be retained to preserve TCC attribution.
