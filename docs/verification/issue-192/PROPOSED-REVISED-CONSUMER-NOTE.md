# Proposed CN-192-R1 — revised real R16 consumer (not approved or implemented)

The draft does not feed changed real document/dependencies to #190's initial
`r16_private` lane or relabel them `synthetic_local`. Both original byte guards
remain intact. `ProofSessionV2.prepare_rebuild` explicitly refuses that path.

## Exact proposed boundary

Add a separately reviewed #192 `PreparedRevisedProofBuildV2` sibling. Its input
must retain independently pinned original R16 document AND dependencies, their
accepted original raw identities, all old packages/targets and exact baseline
compiler output. Revised execution pins must match the actual accepted #202
proposal/result and hash-bound #192 inference/decision, with every A/B/C case
independently current and authenticated. C additionally binds the actual #191
whole-row handoff to staged document AND dependencies, fresh asset/timing/review
bytes, and actual compiled D1. No guessed six-frame duration substitution.

For changed media needs, require new independently authenticated preparation
receipts/ranges, actual probe/PCM checks and complete source sufficiency through
the public #177 materializer/verifier. Preserve retained original/derived media
and authorization. No original receipt edit or claimed new generic P5 profile.

Emit a distinct `issue-192-v2-revised-preflight/v1` record linking original,
baseline, inference, explicit decision, revised execution and fresh package
identities. Do not reinterpret the meaning of #190's initial preflight version.
Its existing NativeProofBoundaryV2 constructor currently accepts only the
initial version. The owning #190 handoff therefore needs an explicit additional
public revised-preflight consumer, including complete shape/currentness and
authority checks. Retain the existing initial consumer unchanged. #192 must
wait for that approved owner-authored change and new frozen API/source handoff;
it may not call `_guard`, `_read`, `_compile` or another private effect helper
to jump this boundary.

## Why / compatibility / acceptance

This is needed only for the eventual real B2 revised R16 rebuild. The current
synthetic seam can use #190's existing lane with independently new temporary
synthetic inputs; it never makes a real qualification claim.

No existing caller breaks. No `/contracts`, generated type, frozen fixture,
golden or accepted test change is proposed. Add owner-specific refusal tests for
original substitution, wrong/stale/unaccepted decision or source pin, stale C
asset/review, insufficient new ranges and mismatched package, plus public-path
combined revision/package checks and review/final evidence after rebase. Any
#190 source delta invalidates affected #192 tests/receipts and requires exact
new source/API pins and applicable combined-tree evidence.

This note does not amend #177's fractional-rate/source-audio native creation
refusals. Those still require their owning #178/#109/#177 qualification route.
Actual installed Studio, provider/acoustic and Producer/visual/listening gates
remain #178/#145. No qualification flag, native bootstrap or new execution
permission is proposed. This note is pending Producer approval and owner routing.
