### Raw versus normalized fields and frame rates

- `qualification_output_native_v2.py:4205-4239` reads *record* `GetStart(False)`, `GetDuration(False)`, `GetEnd(False)` and **raw source** `GetSourceStartFrame`/`GetSourceEndFrame`. For ordinary video the initial `sourceDuration` is `rawEnd − rawStart`, with tightly bounded verified EOF/saturation cases (`4350-4376`, `3809-3820`) and audio exceptions, **not** a general still hold rule. Imported moving/video source `Frames` are actual decoded frames; visual motion inside those frames is irrelevant to source **type**.
- A one-frame still is materially different: the SDK may return raw `sourceStartFrame == sourceEndFrame` even as its *record* duration extends hundreds of timeline frames. `4366-4374` admits exact `0/0` raw with authored start 0 and sets `sourceDuration = recordDuration`. The observed-edited static case at `4528-4535` similarly sets the current duration when the raw getter pair equals the authored source start. `3333-3365` also shows imported still `AppendToTimeline` **source** frame rate is distinct from timeline frame rate, though the resulting semantic record hold is measured on the timeline.
- For a nonzero raw held counter, `4476-4526` requires the source to be still/placeholder, equal raw start/end, `Frames == "1"`, authored start 0, supported matrix/presenter profile, and measured single-frame source times. `_source_time_error_samples` at `3644-3655` converts `(observedSeconds − expectedFrame × secondsPerFrame) × 48000` into exact rational **sample error**, returning `None` for nonnumeric/nonfinite readings. Source start must be within ±1 sample of **0 seconds**; source end within ±1 sample of **one timeline frame** (`1001/24000` s) **or** one imported still frame (`1 / media FPS`). Only then does it coerce the counter to `sourceStart = 0`, `sourceDuration = recordDuration`. This is a very narrow conditional normalization, **not** a generic ±frame tolerance and **not** necessarily true of an unmeasured live still.
- `4287-4309` independently admits a zero-percent frozen *still* clock only for the matrix/presenter profiles and a static source; ordinary video remains at 100% speed. Static source identity, 1-frame media, and time proof therefore matter; a solid-color H.264 clip is still a **video** source.
- The native capture's `recordDuration` is the held **timeline** extent; its canonical `sourceDuration` is deliberately defined as the same extent, *not* 1 source frame and *not* the single-frame media `Frames` property. `GetSourceStartTime` and `GetSourceEndTime` are conditional evidence for normalizing an arbitrary still getter, not a reason to advance the semantically fixed still source by 24 frames. A 24-frame roll represents 24 timeline frames (at 24000/1001, **1.001 seconds**), but a held source does not play 24 successive underlying frames.
