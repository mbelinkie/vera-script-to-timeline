# #336 phase 3 — measured Studio motion, geometry, and refusal envelope

**2026-11-06; fresh public-synthetic Studio run5; phase-3 technical evidence, NOT complete product delivery.** This succeeds the earlier [startup-blocked attempt](phase3-studio-attempt.md). The full, checked-in, machine-readable, privacy-sanitized [decoded frame evidence](studio-run5-pixels.json) retains three public synthetic source hashes, each 48/24/96/144-frame duration, a full decoded-video SHA-256 for every original case, five frame-indexed corner/focus witness sets per case, and exact post-reopen timeline names/durations. A separately checked-in [derived black-matte proof](studio-run5-matte-pixels.json) demonstrates a 12th new *source → still matte → native motion* timeline with hashed lineage and 11 pre-existing render hashes verified unchanged. All originals remain isolated on the Mac; no older project or output was modified.

## Tested native envelope and provenance

- **Installed target:** Resolve **Studio 21.1.1.10** via external local Python scripting; native `.otio` timeline import with an **absolute path**, native Resolve Type 59 Dynamic Zoom and Type 22 scaling effects. Sources: generated public-only **1000×1000 square**, **1600×900 wide**, **900×1600 portrait** colored-corner grids with an off-center magenta marker at source-normalized `(0.75, 0.30)`. **Timeline setting readback: 1920×1080, 24 fps; rendered/exported output: 1280×720, 24 fps.** Both have 16:9 aspect, but these are not interchangeable resolution claims. Export: QuickTime/ProRes 422 to a new, verified writable dedicated Movies folder; FFmpeg decoded all pixels. `ReplaceExistingFilesInPlace=False` was refused by this Studio API and omitted, with an empty unique output path independently guarded instead. No private source or provider was used.
- **Imported/static None:** One native occurrence, **48 frames**, motion disabled. Frames 0/12/24/36/47 are full-frame pixel-identical, with all four source corner witnesses and the magenta marker (approximately `(819,216)`) present. This establishes one source-specific correct static fit outcome without an implicit animation.
- **Imported/linear motion:** Actual output for square source at **24, 48, 96, and 144 frames**, plus wide, portrait and explicitly **fill/cover** cases at **48 frames**. All outputs decoded to exactly the imported occurrence duration. The square fit case's magenta marker moved `(866,180)` → `(824,177)` → `(789,172)` → `(758,171)` → `(731,168)` at frames 0/12/24/36/47. The wide, portrait, and cover cases also moved; see exact per-frame values in the JSON. The different duration rebuilds begin at the same position and have consistent duration-relative progression.
- **Reopen:** After all 11 independently decoded cases, Resolve saved, closed and reloaded `VERA336-SYN-run5`. API readback verified **11 timelines with the original names and exact `[48,48,24,96,144,48,48,48,48,48,48]` frame extents**. The subsequently added matte timeline also survived a second save/close/reopen, resulting in **12 timelines** and one additional **48-frame** occurrence. These are native persistence checks, not mocked OTIO roundtrips. The earlier 48-frame None render additionally survived an independent save/close/load before the remaining cases were imported.

## Verified mathematical geometry (only for the tested route)

The native effect carried raw `dynamicZoomCenter` keys `(0,0)` → `(0.12,-0.08)` and raw `dynamicZoomScale` keys `0.8` → `1.05`, imported in Studio's exported opaque key slots `-86400`/`-85400`. **Those slots are not timeline frame numbers.** For all four tested source/aspect combinations, the observed marker centroids at the five sampled frames agree to within **4 pixels** with:

```text
t = decoded_frame_index / authored_duration_frames
rawCenter(t) = (0, 0) + t * (0.12, -0.08)
rawScale(t)  = 0.8 + t * (1.05 - 0.8)
fitFactor = min(Wout / Wsrc, Hout / Hsrc)    # native fit
fillFactor = max(Wout / Wsrc, Hout / Hsrc)   # native fill
pixelX = Wout/2 + (sourceX - 0.5 - rawCenterX) * (Wsrc * factor / rawScale)
pixelY = Hout/2 + (sourceY - 0.5 + rawCenterY) * (Hsrc * factor / rawScale)

rawCenterX = focusX - 0.5
rawCenterY = 0.5 - focusY
rawScale = 1 / requested_source_relative_magnification
```

This resolves **the measured sign, origin, reciprocal scale and interpolation behavior** for the tested grid and profile. In particular the final decoded frame is fraction `(N-1)/N` of the motion, *not* the ideal endpoint. The projection is implemented as pure calculation in `native_image_motion.native_projected_point` and `native_endpoint_from_focus`, with `measured_framing_preserves_intent` for strict source-edge coverage checks. The endpoint candidate helper only accepts the **observed direction and scalar range**: raw X `[0,0.12]`, raw Y `[-0.08,0]`, raw scale `[0.8,1.05]`; other signs, greater pan, different native magnification, endpoints and nonfinite data refuse rather than clamp or extrapolate. These limits are **not an authorization for arbitrary source bytes or a generalized native capability profile**. The source/profile/epoch-qualified production attestation remains absent, and `production_qualification()` deliberately still returns `None`.

## Small positive proof: black derived still matte preserves moving contain

After observing that direct native fit+zoom crops, the independently verified public `square.png` (SHA-256 `c69871d3...`) was decoded as lossless RGB, **nearest-neighbor resized to 450×450** without stretching, and embedded at `(575,225)` on an opaque **1600×900 black RGB matte**. No motion was baked. `scripts/issue336_studio_matte_probe.py` recorded the exact source hash, derivative hash `ce1cd9d6f18f00ee00b8d50d88222aeafb90f6b9b5223b49d9f81014243f155c`, canvas, content rectangle, resampling, and background color **before** native import. The resulting new OTIO references the *new hashed matte*, not a substituted original. It uses the same separately applied native Type 59 linear moving-zoom effect and Type 22 fit scale. Only this **specific black-matte composition** was tested; it is not evidence of arbitrary background color, fit size, aspect, focus range, formats, or other source bytes.

The 48-frame ProRes render decoded at 1280×720. At frames **0/12/24/36/47, all four original colored corner patches and the magenta focus marker are visible**. The marker moved approximately `(753,270)` → `(700,260)` → `(655,251)` → `(615,243)` → `(582,237)`; the frame-index/duration projection above predicts each within 3 pixels. Every whole-frame checksum differs between sampled times, proving live native motion rather than a pre-baked static hold. Native output hash, full decoded hash, five sampled frame SHA-256 values and witnesses are all in [`studio-run5-matte-pixels.json`](studio-run5-matte-pixels.json).

After rendering, **all 11 previously rendered movie SHA-256 values still matched their pre-matte values**. Resolve saved, closed, reopened and reported the **12 exact timeline names and original 11 durations plus the new 48-frame matte case**. This is a *bounded success for a derived still+black background+native motion on the synthetic source*, not a general automatic matte pipeline. The probe is not a production adapter and must not be silently copied into `v2_package.py` without a source/profile-attested derived-artifact inventory, authoring policy, and verified runtime boundary.

## Tested negative results — do not claim support

| Request/behavior | Actual result | Product consequence |
| --- | --- | --- |
| Fit / nominal **contain** + tested native moving zoom **without a matte** | The square **loses both upper colored source corners at all sampled motion frames**; top is cropped, and lower corners only become visible later. Equivalent witness loss occurs with wide/portrait grids. | **Direct native fit is not qualified as contain.** A *particular* newly tested black derived matte preserves all original source corners on the synthetic grid (see positive proof above), but **general automatic contain/background composition remains unqualified and unimplemented in production**. |
| Explicit cover/fill | Native output moves and intentionally crops; source corners are not visible and the transformed source does not cover every output pixel at all endpoint settings under the measured projection. **Independent FFmpeg pixel inspection at decoded frame 47, output `(1279,360)`, returns RGB `(0,0,0)`**, confirming a black right-edge gap. | Correctly report crop; **do not claim gap-free cover with arbitrary pan/zoom/background**. Reject projected edge exposure rather than hiding black with an unqualified fill. |
| Imported easing values **1 / 2 / 3** | `square-ease-in-48`, `square-ease-out-48`, and `square-ease-both-48` have **bit-identical full decoded-pixel SHA-256** to `square-motion-48` (linear): `b8a88e7ba71e24db...` for all four. | Eased variants **refuse**. Setter/readback success cannot establish visual easing. No silent substitution with linear. |
| Reverse direction, opposite-sign pan, wider center/scale extent, arbitrary source/profile, Free/manual routes, user-selected backgrounds, native trim | **Not exercised / no applicable decoded proof.** | **No optimistic equivalence.** Remain unqualified and refuse. Do not treat a missing test as demonstrated impossibility. |

The per-case full SHA-256, corner/marker coordinates and saved/reopened durations are in [`studio-run5-pixels.json`](studio-run5-pixels.json) and [`studio-run5-matte-pixels.json`](studio-run5-matte-pixels.json). `tests/test_issue336_studio_geometry.py` checks the first set and bounded projection; `tests/test_issue336_studio_matte_probe.py` checks matte derivation, synthetic source preservation, source-edge coverage, decoded native evidence and 12-timeline reopen; `tests/test_issue336_native_image_motion.py`, `tests/test_issue336_studio_qualify.py`, and package tests verify refusal and immutable OTIO behavior without faking production evidence.
