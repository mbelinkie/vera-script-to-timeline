# #367 — Note-attached Research footage: implemented domain handoff

**Status:** bounded authoring-v2 contracts and pure domain commands implemented in #367 phases 1–4; phase 5 owns final validation, mutation audit, independent review and PR delivery. This is **not** a production Research API, footage player, search surface, authoring UI, or Resolve feature. #125 may depict the workflows only once it connects them to this tested domain API.

## Persistence and ownership contract

- `ScriptDocumentV2.stash` persists ordinary Stash rows; `stashOutline` persists note/clip hierarchy (`parentRowId` means *nesting*, not attachment). A **note** (`NarrationBlockV2`) optionally owns one `attachedFootage: { clip: VisualOnlyBlockV2 }`; the clip exists only within that authoritative field while attached, not in `stash[].rows` or the active Draft. Stash counts include the embedded occurrence. Existing documents lacking `attachedFootage` still deserialize unchanged.
- The attached occurrence carries its own `id`, `version`, `researchClip` immutable Research candidate snapshot (project, clip/version, video/source, logged transcript/export selection, creator when available), `frameBinding` if separately supplied, `visualOnlyTiming.selectedSourceRange` if evidenced, and muted/quiet visual policy. The note's literal `text`/`plainDirection` is independent of the clip and of ordinary descendants.
- Active placement of the parent note creates **one** `NarrationBlockV2` with a deterministic *derived* primary visual slot mirroring its embedded clip; it does **not** create a second footage row/owner. Active mirrors are checked against media ID, provenance and selected range, and cannot silently overwrite edited visuals.
- Separate placement moves that **same** clip ID to one ordinary active `visual_only` row and empties the note slot. `stashOrigin.originalAttachedNoteRowId` plus historical parent/sibling anchors records where it may return. The validator rejects overlapping ownership, stale/mismatched source binding and out-of-bounds frames. All successful commands atomically increment `rowEditRevision`; stale/malformed operations refuse without partial changes. `createRowEditSessionV2` Undo restores the complete prior content and ordering (revision monotonically advances).

## Exact public operations

Import from `packages/contracts/src/authoring-v2.ts`. Use `applyRowEditV2(document, expectedRevision, command)` or `createRowEditSessionV2(document).apply(command, expectedRevision)`. Sorting uses `createSortingTrialV2(document).apply(command)` and `resumeSortingTrialV2(savedJson)`. All IDs below are UUID strings; `gap` is the **exact** `RowGapV2` `{ sectionId, afterRowId, beforeRowId }`, each property present with string or `null`.

| `RowEditCommandV2.kind` | Payload beyond `kind` | Tested result / guard |
| --- | --- | --- |
| `create_stash_note` | `bundleId, row, sectionId, parentRowId, afterRowId`, optional `mode: "default_direction" \| "authored"` | Saved compact direction/note; no implicit child attachment |
| `create_stash_clip` | `bundleId, row, sectionId, parentRowId, afterRowId` | Saved ordinary clip, including unresolved Research clip |
| `attach_stash_footage` | `noteRowId, clipRowId` | Consume existing ordinary compact clip into **empty** note slot |
| `replace_stash_footage` | `noteRowId, clipRowId, releasedBundleId` | Consume chosen ordinary clip; release old embedded clip as ordinary child in fresh bundle |
| `detach_stash_footage` | `noteRowId, bundleId` | Release embedded clip to ordinary child; preserve note and descendants |
| `cleanup_blank_stash_note` | `noteRowId, clipBundleId` | Truly empty plain-direction note only: promote attached clip to note position, reparent direct ordinary children; refuse referenced/nonblank content |
| `trim_research_clip` | `clipRowId, edge: "in" \| "out", frame` **or** `clipRowId, edge: "clear_out"` | Change only selected occurrence; reject outward, empty, non-evidenced or stale ranges. `clear_out` restores original **logged** end |
| `place_attached_footage` | `noteRowId, destination: gap` | Empty original note slot and place one visual-only row in exact Draft gap; retain original-owner metadata |
| `place_stash_rows` | `rowIds, destination: gap`, optional `includeDescendants: boolean` | Include ON/default converts ordinary descendants in outline preorder; OFF promotes ordinary descendants to original Stash level. Explicit embedded footage **always** moves inside its note |
| `stash_rows` | `rowIds, bundleId` | Return untouched separate footage to **original unmoved note** only if slot is empty; if occupied, keep ordinary child. Edited footage remains ordinary; missing/moved owner uses strict anchored fallback or refuses ambiguity |
| `set_stash_outline`, `move_stash_rows`, `move_rows`, `edit_row`, stage-direction commands | Existing public command shapes | Sorting/authoring operations remain guarded; `edit_row` cannot forge an embedded attachment transfer |

`StashFootageCommandV2` is the exported union of the six dedicated footage operations above. The Research boundary is also exported as pure `snapshotResearchCandidateV2(input)`, `createResearchClipOccurrenceV2({ rowId, payloadId, orderKey, candidate, frameBinding?, selectedRange? })`, `inwardUseRangeV2`, `withResearchClipUseRangeV2`, and `trimResearchClipOccurrenceV2`. Use the row-edit commands for revisioned document mutations; pure snapshot helpers never save to or mutate the Research service.

## Sorting acceptance, replay and ambiguity

`createSortingTrialV2(baseline)` keeps its own local copy. `trial.apply(command)`, `trial.undo()`, `trial.preview()`, `trial.returnToSorting()`, `trial.serialize()` and `resumeSortingTrialV2(json)` preserve complete command replay, structural revisions and preview read-only behavior under `sorting-trial/v1`. `trial.accept(canonical, "all" | "edits_only" | "sorting_only")` or `trial.discard(canonical)` is a single final decision, gated by exact canonical baseline equality; optional canonical comment reconciliation remains delegated to `resolveSortingCommentsV2`.

- **all:** apply trial's complete validated content plus organization, including trims, attachment transfer, separate placement, source-mirror updates and grouping.
- **edits_only:** retain authored changes (attachment/detachment/replacement/cleanup and bounded trims); reject separate placement and Stash/Draft rearrangement. A pre-existing clip moved independently during Sorting reattaches to its baseline note *in this selective result*, carrying the authored use-range, with no extra row.
- **sorting_only:** keep the trial layout but source the original clip content/range from the canonical baseline; a previously embedded clip placed independently remains **one** ordinary row, and its note slot stays empty. When a note with a baseline attachment is moved into Draft, recompute its derived visual mirror from baseline evidence; no stale or duplicate visual sources.
- **discard:** return unchanged canonical document, without installing pending command snapshots.

The selective projection tracks an existing embedded identity crossing into ordinary row space. It reconstructs complete snapshots by stable identity, not partial replay against a reordered document. It validates projected attachments, recovered slots, relationships and unchanged clip identities before acceptance. **Ambiguous** selective combinations (for example replace an attached clip, then independently place the replacement, or occupy the original slot after moving out its clip) can refuse `SORTING_PROJECTION_IDENTITY_AMBIGUOUS`, `SORTING_PROJECTION_ATTACHMENT_INVALID` or a dependency/validation diagnostic; acceptance leaves the canonical and pending trial untouched. Use `all` or separate the edits in that case. No guessed owner, orphan/ghost clip, partial projection, duplicate media occurrence or silent downgrade is acceptable.

## Synthetic acceptance scenarios executed in phase 4

- Baseline note with explicit attached clip **and independent ordinary child**; inward trim and `place_stash_rows(includeDescendants:false)` then all four outcomes, mirror/source-range comparison, child promotion, reload and untouched return.
- Original attached clip placed independently, then `in`/`out` trim, Undo, preview, trial serialization/replay and four outcomes. `edits_only` retains authored trim on the embedded occurrence; `sorting_only` retains standalone location with original range. Exact author/research source snapshot remains unchanged.
- Authored `attach`, `replace`, `detach`, and empty-note cleanup, each accepted with all four outcomes and tested for conservation of the original clip ID. Return untouched to empty note, return edited as saved ordinary clip, and occupied original-note return retaining ordinary child; no automatic substitution.
- Ordinary child regrouped through `set_stash_outline` while footage is independently placed: selective outcome preserves chosen hierarchy without creating an attached edge to that child.
- Unresolved Research-backed footage retains frozen candidate identity with no frame binding, selected frame range or fabricated source; normalized Sorting and document reload still work. Compile/readiness refusal is covered by phase-3 compiler/consumer tests.
- Malformed/extra command keys, invalid ranges, replay tampering, reused identity and ambiguous content+layout conflicts fail without mutating pending or canonical documents. Four deterministic in-frame cases also assert exactly one footage occurrence under all selective modes.

## Research adapter and production boundaries — handoff to #125

Research's persisted `ClipCandidate`/logged export snapshot contains video ID/URL/title, transcript track/version/selection in **milliseconds**, clip version, project and optional author/timestamps. It **does not** supply an authenticated Timeline integration, verified prepared media hash/bytes, `mediaReferenceId`, exact frame-rate map or a durable ms-to-frame conversion. `frameBinding` must be provided separately for *the same* frozen clip/version and evidenced logged frame interval. The pure adapter checks shape and source consistency; it cannot itself authenticate or independently prove a supplied binding's external provenance. Without that evidence, keep the clip as `unresolved_visual`, and block renderer readiness; do not infer frame counts from milliseconds, treat a completed Research export request as a verified media file, or auto-download/replace a source. Nonspoken direction+clip rows do not acquire invented narration or arbitrary automatic duration.

**#125 may design:** explicit one-clip attach/replace/detach and blank-note cleanup; parent-only/branch placement (with attached footage independent of outline children); trim in/out/clear-out with source-bounded ranges; separate placement, original-note return and occupied/moved/missing-owner fallback; Undo; Sorting preview/reload and four finish outcomes; a visible refusal/unknown/unresolved state. **#125 must not depict as working:** Research catalog search/auth/export/player/transcript resolution, preview bytes/verified media discovery, live collaboration, arbitrary multi-visual timing, automatic media recovery, or any UI that has not yet called the exported operations. Their production owners remain #65, #77/#78, #80/#81/#83 and #125 itself as scoped in #367. No Resolve run, provider call or personal media action is part of this contract test.
