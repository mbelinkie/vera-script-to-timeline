The v2 narration shape also preserves the existing optional v1 `annotations` and `performanceBeats` arrays exactly, including their typed range, identity, version and prompter-inclusion fields. The accepted #156 plan explicitly removes `visualEvents` and `hostVisibilitySpans` as v1 narration surfaces; it does not authorize deleting these annotation and performance records.

Where the accepted sources prescribe the evidence meaning but not JSON field spelling, this schema uses the following bounded forms: Unplaced `reason` is required nonempty readable text (no invented reason taxonomy); optional `priorAnchor` is a typed word/range/point anchor; `sourceOrderKey` is a string order key; and `neighboringBlockIds` is a bounded list of UUIDs. A point anchor is a closed `word`, `between_blocks`, or `event_edge` variant. A timed placement has `start`, `end`, and `durationMs`; JSON Schema requires any consistent pair to be present, while cross-anchor and all-three agreement remain semantic checks. Overlay events use that timing form and have no authored parent, layer, or ordinal. The active narration sequence is required for active narration; a missing/empty sequence is not repaired by the schema, and stale references remain serializable for later validation.

Both schemas use Draft 2020-12, local references, closed objects, explicit schema-version constants, and safe-integer bounds. `PresenterStillReference` permits only the accepted `local_import` and `captured_frame` provenance variants. Omitted settings inherit; `null`, unknown fields, and unknown versions are rejected. The document schema preserves explicitly allowed draft-invalid states such as a return with no inpoint and unresolved anchor references; resolving anchors and checking cross-record identity remain semantic responsibilities. V1 generation stages only the five filenames already in the generator's explicit TypeScript list; v2 files must never enter the v1 Python output group.

The test samples will be synthetic and kept in the issue-owned test source; the verification record will pin the accepted source documents and the resulting sample/schema hashes. Schema tests cover allowed settings data at both scopes and omission versus `null`; precedence itself is a resolver behavior and is not claimed by JSON Schema. Existing v1 schemas, generated TS/Python files, accepted fixtures, goldens, and tests remain byte-identical.
