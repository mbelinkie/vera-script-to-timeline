# #123 reconciliation annotation rules

Producer accepted the exact r2 artifact on 2026-09-27. These rules are the
accepted #123 comparison annotation authority, with retained prototype
limitations and downstream boundaries in [ACCEPTED-HANDOFF.md](./ACCEPTED-HANDOFF.md).

Status: **source of truth for annotation in the experimental compact #123 pilot** and for the next correction/QA pass. These rules consolidate the Producer's later decisions and supersede contradictory annotation descriptions in older #123 prompts, page harness copy, and renderer comments. They do **not** change the accepted S03/S05 artifacts, production contracts, or the scenario/decision model. If a case cannot satisfy a rule without changing those boundaries, report it rather than inventing a new signal.

## What each signal means

1. **Source and time come first.** `Current script` is the literal canonical script and is visually neutral. `Current Resolve` is the last-read timeline; green and red there identify Resolve-originated differences from the script. `Script after reconciling` is a labeled, not-yet-applied result, shown only when the selected script result matches neither literal source. A correction queued for the next Resolve update is not applied to, or painted onto, Current Resolve.
2. **Narration content is not visual coverage.** Spoken words that are identical in both sources never become green merely because a clip starts, stops, covers them, or exposes the presenter. A text-diff color means the *words themselves* changed. Keep the ordinary S03 bold On Camera versus regular VO typography for the picture actually visible in each source. For a visual change, point to its range with its own start/end marks and card, not green text fill. This rule applies to Changes 4, 6, 8, 10, 11, 15, 16, 20, 21, and 22.
3. **Change color goes on the changed thing.** Green means an added/replaced object, changed placement, or changed property/boundary in Current Resolve. Red means material removed or absent in Current Resolve. Color is always reinforced by a label, shape, strike, or accessible description. Neither color alone establishes whether something has already happened or is only previewed.
4. **Type and change are separate axes.** Neutral cards may use light type tints (On Camera, footage, still/web capture, Graphic, music). When an *entire* visual is newly added or replaced, a pale-green fill and clear green border override its type tint; the card's type remains identifiable by its short label, image, and details. **Every transparent Graphic has a fine dashed card perimeter** in both source views: green for a newly added Graphic, muted Graphic-colored for an existing one. The dash pattern means transparency; its color means change state. When only one property of an existing visual changes, retain the type tint and mark only that property green.
5. **Range marks identify the visual, not new words.** A newly added visual's start and end marks/connector are green with its green card, even when it covers unchanged narration. A same-range replacement changes the card identity, not the existing range marks. If an existing visual's start or end changes, only the affected endpoint and a useful changed duration receive focused green; the unchanged endpoint, card, narration, and underlying visual remain neutral. A clip-to-row swap may mark the changed pairing, but not imply the clip asset, duration, or spoken words changed.
6. **Inspection is temporary, not another diff.** Hover or keyboard focus reveals the actual S03 range for one visual, including ranges across rows. It temporarily takes precedence over persistent difference marks and restores them on exit. Persistent dotted/dashed underlines across unchanged narration are not the Graphic-range indicator; do not replace them with a second always-on text highlight. Range details, source in/out, and other secondary numbers belong in click/keyboard details, not on a crowded card face.
7. **A newly visible base is not a newly added object.** When an existing B-roll clip ends earlier and reveals the presenter, the existing On Camera card retains its light On Camera type tint in Type tints mode (or white in White cards mode). It does not turn green. The B-roll's changed endpoint and duration carry the green signal.

## Deriving visual annotations from a diff

Use the structured reconciliation result, not text color, card position, or a filename heuristic. For each visual slot/instance, the comparison needs its stable identity or explicit cross-source match, media/layer type, source-specific start and end **word anchors** (including row identity), and a classified operation. A Need to Find request is not footage, but it **is a visible, ranged visual-intent card**: it can be the script-side slot that Resolve footage fulfills. If identity or operation is ambiguous, expose that uncertainty for review; do not guess a replacement from matching words or a reused media file.

Apply these rules to `Current Resolve`; `Current script` remains the neutral literal source:

| Classified difference | Card / item | Start and end marks / connector | Narration |
| --- | --- | --- | --- |
| Visual added where the script had no visual or ranged request slot on that layer | Green added card (or green new music rail) | Both marks and its connector green | Unchanged words neutral |
| Media substituted for an existing visual or ranged request slot over identical anchors | Green replacement/fulfilled card | Both unchanged marks and connector neutral | Unchanged words neutral |
| Same visual instance assigned to different row/word anchors | Keep its ordinary type tint; signal the move/pairing separately | Green only for anchors that differ. If both endpoints now belong to a different narration row, both marks are green, even if the row-local length is identical | Unchanged words neutral |
| Same visual instance, same anchors, changed setting only | Ordinary type tint | Marks and connector neutral; box only the changed property | Unchanged words neutral |
| Whole row moves with its words and visual together | Green treatment around the moved row/group | Visual's **relative** word anchors and marks stay neutral; do not misclassify as a clip-to-row swap | The words move with the row but are not a text edit |

Thus **Change 17** is a same-slot fulfillment: the visible Need to Find card and `housing_waterline_0911.mov` cover the same words. The footage card is green because what fills the slot changed, while both Resolve range marks, connector, and unchanged narration are neutral. If the footage actually extends or shortens that request's range, color only the changed endpoint(s). **Change 18** is different: `hull_record_cu_0916.mov` and `keel_lift_0916.mov` both existed, but each now attaches to the other narration row, so both pairs of Resolve marks are green; their cards retain footage type tint and their spoken words remain neutral. In each case, the script-side marks are neutral. **Change 12**, a same-anchor media replacement, follows the Change 17 pattern: green replacement card, neutral marks. The classifier must distinguish substitution from changed visual-to-word assignment before assigning colors.

For implementation, compare anchors by stable row and word identity, **not** by the displayed word string, screen position, or approximate duration. First match the script's visual **slot**, including a ranged Need to Find/placeholder slot, to the Resolve visual when the reconciliation evidence supports fulfillment. Then set `startChanged` and `endChanged` independently. Addition with no matched slot paints both marks; substitution/fulfillment at identical anchors paints neither; a matched visual moved to another row paints each endpoint whose row/word anchor changed. Moving a whole row with its visual does not change either visual-to-word anchor. If the reconciliation model cannot tell an addition from a substitution or match visual slots across sources, the UI must surface an unresolved match rather than choose green marks by appearance.

## Annotation by change type

| Resolve-originated change | Current Resolve annotation | Current script / selected result |
| --- | --- | --- |
| Whole row or atomic group added | One green field/border around the inserted row or group. New visual card is green; unchanged neighboring rows stay neutral. | Literal script shows a neutral `No equivalent row in the current script.` marker, not a fabricated row. Accept shows the Resolve content; reject queues removal without recoloring Current Resolve. |
| Whole row or consecutive rows removed | Readable former rows appear only as **red, struck comparison evidence**, one atomic group; they are inert, not live Resolve content. No shadow or extra label bar. | Literal script rows are neutral. A queued restoration is explained as future work, not shown as already restored. |
| Whole rows moved or reordered | Green boundary/placement tab around the moved passage; an origin marker identifies where it left. Words, clips, thumbnails, and properties inside remain neutral unless independently changed. Show real neighboring rows at both locations. | Literal script retains its original placement with no Resolve-specific location labels. One move is counted once. |
| Two clips swap fixed narration rows | Green signals the changed **clip-to-row pairing** (one short swap label or equivalent link). Both clips' row/word anchors changed, so both endpoint pairs are green. Their footage cards keep their ordinary type tint; the source media, sound, range length, narration, and row order stay neutral. A type label and one pairing signal may coexist here because the two clips must be read as linked. | Script keeps its actual original pairings and neutral marks. Do not make a half-swap outcome. |
| Whole rows swap | Green group boundary indicates order change. Each row's words and visual travel together and remain internally neutral. | Script shows original row order, with the same surrounding context. |
| New opaque clip, including a bumper over older narration | Entire new card and its start/end range marks are green. Give it one concise provenance/type label; unchanged narration remains neutral, but its On Camera/VO weight follows the visible picture. | Script has its literal older visual or neutral no-equivalent state. A hybrid result is separately labeled, not painted onto either current source. Do not imply that hidden footage was deleted. |
| Existing clip replaced over the same range | Replacement card is green, but the unchanged range marks, words, sound, and duration are neutral. | Script shows its literal earlier clip and the same range neutrally. |
| Resolve footage fulfills a ranged Need to Find request | Treat the request as the existing visible visual-intent slot. If the clip covers the same words, its replacement/fulfilled card is green but both range marks and connector stay neutral. If its coverage differs, color only the changed endpoint(s). Closing or retaining the request is a separate decision. | Script shows its literal Need to Find card with neutral marks; it does not show the candidate clip as already accepted. |
| New transparent Graphic over an existing base | The new Graphic card is green, with a rendered preview, independent green start/end marks, and a fine **green dashed card perimeter**. There is no persistent dashed underline under the narration. The unchanged On Camera, footage, or still base stays type-tinted and visibly continuous. The Graphic is a layer, not a cutaway or return. | Script has only the base until accepted. A spoken trigger cue appears on its word only when that cue exists in the viewed source/result. |
| Existing clip or Graphic start/end/range changes | Existing card keeps its type tint and identity; a transparent Graphic keeps its fine **muted Graphic-colored dashed card perimeter** in both sources. Mark the **changed boundary** and a short changed duration (if useful) with a crisp green treatment. Unchanged spoken words stay neutral, including words newly covered or newly On Camera. No persistent dotted range underline or green word fill. Hover/focus reveals the full old/new range in its respective view. | Script keeps its literal boundary and neutral duration. A selected correction does not change Current Resolve. |
| Existing framing, sound, trim, motion, fade, or other property changes | Green box around only the changed value (`Tight`, `~4.6s needed`, fade-out, motion, etc.). Card type tint, thumbnail, and unaffected values remain neutral. Reveal source in/out and other numbers in details. | Script's literal value is neutral, in the same position when practical for comparison. |
| Music bed added in Resolve | Violet identifies the item as music, while the **new bed's entire thin rail and both start/end word anchors are green** in Current Resolve. The spoken words and other row content remain neutral. | Current script shows no bed, not a phantom rail. Beds may legitimately cross rows and headings without merging visual rows. |
| Existing bed's placement endpoint changes | Keep the bed's identity violet/neutral and mark only its changed word anchor and affected rail interval green. Do not color unchanged narration or the other endpoint. | Script shows its literal anchor and span neutrally. Source trim is a separate property from timeline placement. |
| Existing bed's fade or other setting changes without moving it | The thin rail, start word, out-word, and span remain the same violet/neutral bed in both views. Only the changed setting is green in Current Resolve, in a legible box in the same label position where Current script shows its neutral value. | For Harbour Close Bed, both sources run from “just” to the out-word “coast.”, about 15s. Current script has `Fade out 2.0s`; Current Resolve has `Fade out 4.5s`. The 20.0s *source out-point* is not the narration out-word, and the fade duration is a ramp inside the unchanged placed span. Do not imply the bed or its endpoint moved. |
| Spoken phrase cut in Resolve | Cut words are red and struck **comparison evidence**, not spoken and not On Camera. Surviving words are neutral. If the cut displaces a clip anchor, green marks its changed start boundary/duration, not the surviving word. | Script shows its full literal words and original anchor neutrally. |
| Independent script rewrite conflicts with a Resolve-added visual | Each source shows only its literal words and visuals. The rail names the conflict and offers explicit merge choices. Do not green either source's unchanged words just to indicate difference. | A hybrid gets `Script after reconciling` because it matches neither source. |
| Existing visual fully covered by new opaque clip | New top visual is green. The entirely hidden old clip is smaller, inset, gray, and labeled dormant; it is not red-struck or said to be deleted. Partially hidden footage is depicted only through its actually visible interval. | Script shows its actual older visible arrangement. |

## Card-face and range guardrails

- One primary pill on an ordinary card face; do not stack `Logged clip` with `Added in Resolve` or duplicate status prose. A linked clip-swap pair may show one additional short pairing indicator beside its type label. The type and provenance still need clear accessible names and on-demand details.
- Footage cards show a thumbnail when enabled, one actual/estimated length, sound state, and zoom if applicable. Full-sound transcript appears only for a standalone clip; B-roll under narration is No or Quiet sound.
- A Graphic is labeled **Graphic**, not `Onscreen Placeholder` when the media is an existing/editable Fusion comp. Show a rendered preview, concise name, and relevant length. Never let its face clip horizontally at 1024 × 768 or 0% thumbnails.
- A visual with one independently timed range may omit its visible ordinal if its endpoints/card remain unambiguous. Keep numbers for multiple confusable ranges/cutaways. Do not change stable IDs or accessible descriptions.
- Brackets cannot orphan: opening bracket + ordinal + first covered word, and last covered word + ordinal + closing bracket, stay together when wrapping.

## Correction and QA protocol

Correct shared renderer/page-local annotation rules before one-off case styles. Then, for each of the 22 changes, record: change type; expected changed entity; what is green/red on **Current Resolve**; whether **Current script** is literal and neutral; whether selected outcomes show the right source or a justified result; range inspection; card-face legibility; and any contradiction. Check both `1024 × 768` and `1280 × 800`, normal/small text, and thumbnail `0%` and default. Report severity and evidence by change number. If verification is blocked, name the unverified cases and leave them open.

Keep these previously observed failures as regression checks; they are not a claim that each still exists in the current page:

- **Change 9:** a newly added sponsor bumper has a green border but retains footage-blue fill. Under rule 4 its whole card should be green.
- **Change 11:** existing words `the north wall` are green because the clip starts later. They should have ordinary On Camera bold; the changed clip start/duration should carry green.
- **Change 22:** persistent dotted Graphic-range underline makes unchanged words look annotated; its card says `Onscreen Placeholder`, uses a generic image, and overflows/clips at the narrow viewport. The existing Graphic should stay type-tinted with only its changed endpoint/duration green.
- **Change 17:** a green fulfilled-footage card paired with neutral range marks is **correct** when the visible Need to Find slot and the clip cover identical words. Do not color its marks merely because the media is now real; verify any actual anchor difference separately. The script's request stays neutral.
- **Change 18:** the two clips exchange narration rows but neither narration nor row order changes. Both clips' Resolve endpoint pairs signal their changed word anchors; their ordinary footage fills, media identities, sound states, and words do not look newly added. Script-side marks stay neutral.
