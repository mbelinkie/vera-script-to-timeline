## Correction: automated and manual audio controls

**Plugin-proven automated silence control:** `TimelineItem.SetClipEnabled(False)` on the tested audio occurrence. On Studio **21.1.1.10**, Workflow Integration W1 disabled A1, read back disabled state, and generated subtitles/rendered output containing the A2 numbers without A1 NATO words ([W1 result](../issue-149/workflow-reruns/w1-result.md)). This is the bounded automation alternative to mapping mute.

**Manual controls:** W2's track Mute and Solo were set by the producer in Resolve's interface. Current-timeline OTIO flags and rendered output verified their effects, but this does not prove an automated setter ([W2 result](../issue-149/workflow-reruns/w2-result.md)). No documented `SetTrackMute` or `SetTrackSolo` setter was found in the installed scripting reference.

**Unverified through the plugin with output:** `Timeline.SetTrackEnable(trackType, trackIndex, enabled)` exists in the installed reference. Older #141 calls/readback are state evidence only; no retained WI setter→render test proves it silences the program. Do not assume equivalence to a person's Mute click or to Console behavior. VERA cannot currently offer it as a proven automated silence control. **No additional test was run for this correction.**

**Excluded control:** `SetSourceAudioChannelMapping` mute is unavailable as a VERA WI output control in the tested **21.1.1.10** contexts. It read back true without reducing the A2 pilot or removing number words; Claude's Console setter worked on the same-project comparisons. Internal cause remains unknown.

## Three adopted decisions

1. **Replaced files (W6):** detect changes by content hash. For an approved replacement, change its filesystem modified time, call `RelinkClips`, then verify the decoded source with a render before accepting the replacement or promoting a baseline. Atomic replacement with kept modified time rendered source ID 1; changed modified time plus relink rendered source ID 2. Online status, Date Modified, source UID and `RelinkClips=True` are insufficient. This reload procedure is supported for the tested media/cache context; other codecs/cache paths need their own output check. This investigation does not authorize changing production source files.
2. **Mapping mute (W3):** treat `SetSourceAudioChannelMapping` mute as **unavailable as an output control from VERA’s Workflow Integration plugin**. WI direct rendering, Console rendering after WI mute, and opening Fairlight after WI mute all retained pilot 0.01986 and all eight A2 number words despite `mute:true`; silence required ≤0.001 and no numbers. Claude’s Console-applied setter silenced A2 even on a duplicate of Codex’s timeline and on a fresh timeline using Codex’s media. Use the plugin-proven clip disable operation for automation, with verified output. Track Mute/Solo were set manually in W2; SetTrackEnable remains unverified through the plugin with a render. Solo changes the audible mix, so select it only when that mix is the intended operation. A stored mapping flag must never count as proof of speech removal. The internal cause is unknown; diagnosing it is not required for this safe product decision.
3. **What the edit actually says:** obtain program speech from Resolve’s own edited-mix transcription, `Timeline.CreateSubtitlesFromAudio()` on a disposable duplicate, or from analysis of a verified render. W1 confirmed linked-cut, picture-only-cut and disabled-A1 speech differences against renders. Source `MediaPoolItem.GetTranscription()` describes source words; clip ranges, mute/enable flags and other structural API readback do not establish the audible program. The timeline-proxy getter still returned `None`. `CreateSubtitlesFromAudio` is itself an API operation, but its generated transcript is distinct from structural readback. It adds a subtitle track, runs asynchronously and requires the tested Edit-page context; preserve the original timeline. Subtitle segments/frame timecodes do not supply sample-exact word edges. Coverage, freshness, ASR mistakes and ambiguous partial words remain explicit gates under #146.
