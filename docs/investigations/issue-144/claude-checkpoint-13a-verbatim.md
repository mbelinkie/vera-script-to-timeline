### Significant observations (not blockers, but should be surfaced, not buried)

1. **This file does not itself gate `real_issue145`.** `_capture` (`roundtrip_wi.py:405`) and `perform` (`:678`) both accept `evidenceLevel in ("synthetic_injected", "real_issue145")` as structurally valid and pass it straight through into every returned envelope (e.g. `:495`, `:888`, `:922`, `:963`). Nothing in this module independently restricts or re-labels that value — the docstring is honest about this ("Live qualification belongs to #145"), and you've confirmed the actual refusal gates in `roundtrip_audio.py`/`roundtrip_omission.py` are unchanged and still closed, so I don't think this is a defect. But it means the *only* thing preventing a future driver from emitting a `real_issue145`-labeled result through this exact code path is the unchanged downstream gate — worth saying explicitly rather than letting a reader assume the WI reader itself enforces the lane.

2. **PCM extent math may refuse legitimate non-integer-frame-rate renders.** `perform`'s stereo-PCM check (`:936-942`) computes `count = Fraction(durationFrames * 48000 * denominator, numerator)` and requires `count.denominator == 1`. For a drop-frame/NTSC-style rate (e.g. 30000/1001), samples-per-frame at 48kHz is `1601.6` — not an integer — so this would only ever pass when `durationFrames` is a multiple of 5, refusing otherwise-valid full-program renders at other durations. This fails closed (refuses rather than silently mis-measuring), consistent with the project's philosophy, and it's strictly more correct than a hardcoded 25fps assumption — but it's untested here (fixtures are all 25fps) and worth confirming against whatever frame rate #145's actual target build will use before relying on it.

3. **Tracks dict construction reads as a manifest-fallback at first glance but isn't one.** `read_native:210` does `tracks.append({**track, "name": name})` where `track` comes from the manifest list. This is safe only because the preceding `fact(name == track["name"], ...)` (`:209`) already forced equality — so by construction the manifest and native values are identical when this line runs. I'd still add a one-line comment, since "spread the manifest dict and overwrite one field" is the exact shape of the anti-pattern you're asking me to hunt for, and a future edit that reorders those two lines could silently reintroduce a real fallback.
