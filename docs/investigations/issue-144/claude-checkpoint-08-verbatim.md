## 1. Fabricated echoes, unproven identity, stale observation, evidence lane

The three disclosed defects are genuinely fixed, confirmed by trace, not just by the passing tests:
- **First-baseline replacement identity:** `_occurrence_identity` (`roundtrip_proof.py:217-241`) correctly rejects a capture response whose claimed `itemUid`/`mediaUid` per `eventId` differs from the pre-established `identity["occurrences"]` map, confirmed via `test_first_baseline_must_retain_verified_native_occurrence_identity`.
- **Symlink escape:** `_destination` (`roundtrip_proof.py:57-63`) checks every path component, including the target itself, for `is_symlink()` *before* any `mkdir`/write — confirmed the check runs ahead of `path.parent.mkdir(...)`, and the test shows the symlink target directory stays empty.
- **Status field:** `status` action now returns `{"status": "bound"|"unbound", ...}` (`roundtrip_proof.py:154-161`).

**Finding (Medium, architectural limit rather than a #144 bug — `roundtrip_proof.py:247-260`, `issue-144-semantics.ts:57-84`):** the capture `request` object (`basis`, built in `_fresh`) hands the capture function `manifestPath`, `packageRoot`, and `expectedIdentity` directly. Every field that `validateObservation` subsequently cross-checks — `sourcePath`, `sourceHash` (against `source.contentHash`), `trackId`/`trackKind` — is independently derivable from those same local files, and `_occurrence_identity` only checks the capture's claimed `itemUid`/`mediaUid` against the identity map it was just handed. So a capture implementation that simply *reads the package and manifest* and echoes values back, without ever touching Resolve, passes every check in the pipeline — including the "equal adjacent observations" freshness check, since a package-echoing fabrication is perfectly stable by construction. This is correctly scoped out for *this* segment (the test's `Boundary.capture()` is honestly `synthetic_injected` and the prompt explicitly disclaims real WI observation here), but it means the file-staged protocol cannot, by itself, cryptographically distinguish a genuine live Resolve read from a local-file echo. **Minimal fix:** don't try to solve this in the protocol — record it explicitly as a #145 readiness gate: the real capture adapter must be independently reviewed to confirm it actually queries live Resolve state for geometry/hash fields rather than reading the package/manifest, since no test built on top of this file protocol can verify that distinction for you.

## 2. Immutable publication, path containment, fault handling, capture consumption, replay

- **Path containment:** confirmed above, no gap found.
- **Process-fault handling:** `_semantic`'s `subprocess.run(..., timeout=300)` raises `TimeoutExpired` before any `envelope`/`result` is constructed (`roundtrip_proof.py:337-347`), so a timeout can never masquerade as a genuine semantic `"refused"` result — the inline comment's claim holds at that layer, confirmed by trace.
  **Finding (Low, `roundtrip_proof.py:756-765`):** at the outer CLI (`main()`), both a genuine semantic refusal (`ProofBuildError`, which subclasses `RuntimeError`) and a process-level fault (`subprocess.TimeoutExpired`, `OSError`) collapse to the identical `{"status": "refused", "reason": ...}` shape and exit code 2. A caller inspecting only `status` (not the free-text `reason`) can't tell "your input was evaluated and rejected" from "the process hung for 5 minutes." Minimal fix: give process-level faults their own status value (e.g. `"fault"`) distinct from `"refused"`, or document plainly that `reason` text is the only disambiguator today.
- **Capture consumption:** `consumed.json` correctly excludes a used attempt from `pending` (`roundtrip_proof.py:264-270, 317-325`), forcing a fresh nonce on the next capture — confirmed by `test_file_staged_capture_resumes_one_request_and_cached_response_is_not_fresh` and by tracing the exclusion filter directly.
- **Same-decision replay:** `_decide` delegates to `_retained_decision` when a receipt already exists (`roundtrip_proof.py:509-512`), which **re-executes** the actual semantic CLI on the frozen inputs (`self._semantic("decide", ...)`, line 596) and requires the stored receipt to equal a freshly recomputed `expected` dict byte-for-byte — this is a genuine replay, not a cache hit, confirmed by `test_changed_completed_decision_receipt_cannot_authorize_replay` tampering with one field and getting caught.
