### Verification trace (what I confirmed, and how)

**Host-derived auxiliary routes, never from files, on every replay.** `OmissionProof.composition()` (`roundtrip_omission.py:668-726`) builds `expected_auxiliary_routes` entirely from `inspected["result"]["visualManifest"]` — the actual compiled preview returned by the semantic CLI's `compose` action — by copying each baseline route's static fields (`id`, `sourceId`, `controls`, segment `uid`/`speed`/`enabled`/`online`) and overwriting *only* the four range fields with values read from the compiler-preview `event["recordRange"]`/`event["sourceRange"]` (lines 712-724). Nothing here reads `profile.json` or any evidence/operator file. This runs inside `proposal_report()`, which is itself fully rederived on every `retained_report()` replay (line 838), so it is recomputed every time, not cached from a first attempt.

**Structural separation from primary-support decomposition.** In `roundtrip_audio.py`'s `verify_omission_evidence`, the new allowance block validates each approved route independently, then the per-route decomposition loop does `if old["id"] in approved: continue` — a clean skip with an explicit comment tying it to the design intent. Confirmed via `test_issue144_composition_audio.py` that an auxiliary-only "support" entry in `profile.json` (`tokenId: "auxiliary-only"`) never leaks into `omittedTokenIds`.

**Primary narration can never be smuggled in as "auxiliary."** Both layers independently refuse this: `roundtrip_audio.py` requires `old["sourceId"] != primary_source_id` for any approved entry, and `roundtrip_omission.py`'s `composition()` requires `event["sourceId"] != self.primary["sourceId"]` (line 709). `test_issue144_composition_audio.py`'s malformed-allowance case `{"audio:1": ..., "audio:2": ...}` (primary disguised as auxiliary) is explicitly exercised and refused.

**Forgery resistance of the allowance itself.** The allowance requires `expected == new` (must match the actual fresh capture exactly) and `expected != old` (must represent a genuine change), plus identity/control/segment-flag equality to baseline. The test file exhaustively tries: empty, 1-entry, 3-entry/unknown-id, forged `uid`, forged `recordStart`, forged `sourceEnd`, and a changed `gainDb` control — all refused. It additionally zeroes the rendered program audio and confirms the geometry-correct allowance is *still* refused, proving the auxiliary bypass only affects support-decomposition inference, never the physical mix-consistency check.

**In-memory-only visual projection, host side too.** `composition()` writes only `raw_inputs` (the real baseline/current document, dependencies, manifest, and raw — not projected — observations) to `composition-inputs.json`, and only reads back `visualManifest`/`visualReport` from the CLI envelope. No "projection" field exists anywhere in the TS output (confirmed again via `issue-144-proof-cli.ts`'s result assembly and the vitest assertion `expect(receipt.result).not.toHaveProperty("projection")`), and the Python side never requests or stores one.

**Mode-bound, non-mixable accept/reject.** `OmissionProof.choice()` validates a single scalar `choice: "accept"|"reject"` field via strict `_shape()`, with schema `issue-144-composed-decisions/v1` required when `self.composed`. There is no per-edit granularity in the schema, so "mixed" partial acceptance is structurally impossible, not just discouraged. Final classification requires `result["status"]=="supported" AND (not composed OR inspection.ok)` (`proposal_report`, line ~800) — both the audio and visual tracks must independently pass.

**Default omission-only path is untouched.** `expected_auxiliary_routes` defaults to `None`; when `None`, the entire new validation block in `roundtrip_audio.py` is skipped, reproducing prior behavior exactly. `self.composed` gates every new branch in `roundtrip_omission.py`.
